Load `zwei-orchestration` and `zwei-quality`, plus `zwei-go`, `zwei-angular`, and `zwei-database` for the affected layers. Derive a test matrix from acceptance criteria, run narrow checks then required gates through supported Docker-backed Make targets, preserve and inspect browser artifacts, and report defects without weakening assertions. For full local browser acceptance, prefer `make e2e-parallel`; verify its two independent projects overlap, all discovered specs run exactly once across the file-based groups, development services remain healthy, and both run-ID artifact directories are retained. Use `make e2e` only for the serial workflow and `make e2e-one` for focused diagnosis; those legacy targets share the development Compose project. For Coturn changes, use isolated `make e2e-turn`, verify anonymous STUN suppression, bounded UDP 401 responses, authenticated UDP/TCP relay, renewal/restart/retry, and inspect all retained browser screenshots. Release plumbing changes also require the release, digest-manifest, and Coturn contract scripts. Do not edit the candidate. Use the orchestration handoff contract.
